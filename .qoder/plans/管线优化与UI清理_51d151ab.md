# 管线延迟优化与总览页重构

## 延迟分析

当前完整路径的首 token 延迟：**15-35s**（哲学类复杂问题可达 1.5min）

延迟分解（串行）：
- 晴 LLM fallback（规则未命中时）：2-5s -- action_type 判断已无用但仍在消耗时间
- 遥 格式指引 LLM：**5-15s** -- 每次调用，无缓存，**最大瓶颈**
- 玄 首 token：2-8s -- 受超长 system prompt 影响

## 新管线设计

```
用户消息 → 焕(异步启动,始终运行) + 晴(使用上轮情绪上下文推测用户行为)
                                          ↓
                              遥(静态模板,0ms) → 玄(流式输出)
                                          ↑
                              焕完成 → 注入当前情绪给玄
```

核心变化：
- 焕始终运行（不再由 need_emotion 控制是否启动）
- 晴的职责从"分类 chat/task"转为"结合情绪上下文推测用户行为和需求"
- 遥从 LLM 调用改为静态模板（消除 5-15s 延迟）
- 晴使用上一轮情绪数据做判断（不等焕完成，避免串行延迟）

## Task 3: 遥的格式指引缓存 + 管线优化（后端）

**最大延迟优化，通过缓存消除重复 LLM 调用（5-15s → 命中缓存时 ~0ms）。**

依赖 Task 2 完成（共享 agent.py）。

### 3a. `backend/app/ai/agent.py` — _generate_format_guidelines 添加内存缓存
- 缓存 key：`(user_id, emotion_category)` — emotion_category 按主情绪归类（如 positive/negative/neutral/intense）
- 缓存 TTL：30 分钟（同一情绪类别下，格式指引无需频繁更新）
- 实现方式：类级别 `dict` + 时间戳，命中则直接返回，未命中则调用遥 LLM 并写入缓存
- 情绪类别映射：将焕返回的 primary_emotion（开心/兴奋/满足→positive，难过/焦虑/愤怒→negative，平静→neutral，强烈情绪→intense）

```python
# agent.py 内部缓存结构
_format_cache: dict[str, tuple[str, float]] = {}  # key → (guidelines, timestamp)

def _get_emotion_category(self, emotion_record) -> str:
    """将具体情绪映射到大类"""
    ...

async def _generate_format_guidelines(self, user_message, emotion_record):
    category = self._get_emotion_category(emotion_record)
    cache_key = f"{self.user_id}:{category}"
    now = time.time()
    if cache_key in self._format_cache:
        guidelines, ts = self._format_cache[cache_key]
        if now - ts < 1800:  # 30 min TTL
            return guidelines
    # Cache miss → 调用遥 LLM（保留现有逻辑）
    guidelines = await self._call_yao_llm(...)
    self._format_cache[cache_key] = (guidelines, now)
    return guidelines
```
